# Воркфлоу для каждой задачи

docker exec. В этом docker контейнере отведен для тебя аккаунт гитхаб и все необходимое.
Рабочее место нашего проекта находиться в `/home/5bw/` (не `workspace!`).
Не забывай перед началом работы сделать `git pull origin dev`.
Ты как отдельный разработчик!
Скриншоты щас можешь сохранять в 5bw121/.tmp/ на хост машине, чтобы тебе было удобно их смотреть.

Я разрешаю тебе использовать на хост машине /Temp/ для того чтобы ты потом просто безпасно копировал в /home/5bw через `docker cp`

1. **Ветка**: перед началом работы создай новую ветку от актуального main,
   назови её осмысленно (feature/<кратко-что-делаем> или fix/<баг>).

2. **Реализация**: пиши код, коммить логическими шагами с понятными сообщениями.

3. **Сборка и деплой тестового билда**:
   - Выполни `./build_web.bat`
   - Перейди в `scripts` и выполни `py upload_build.py`
   - Сервер вернёт JSON вида:
     `{'info': "File 'build.zip' uploaded successfully", 'url': 'http://127.0.0.1:8989/get_test/<id>'}`
   - Сохрани этот `url` — он понадобится в двух местах ниже.

4. **Тестирование через Playwright MCP**:
   - Открой `url` из шага 3 через Playwright MCP.
   - Протестируй релевантный функционал (то, что относится к задаче).
   - Если что-то не работает — почини код, вернись к шагу 3 (новый билд + новый upload + новый url)
     и повтори тестирование. Не создавай PR, пока не убедишься, что всё работает.
   - Используй уже созданный input Bridge (misc), по надобности ты можешь его модифицировать. 
   - Не забывай делать скриншоты для проверки, все ли на месте.

5. **Pull Request**:
   Когда уверен, что всё ок — открой PR в https://github.com/askar102/5bw.
   Важно: кидай пуллреквест на ветку `dev`
   Описание PR строго в следующем порядке:

   1. Первая строка — ссылка на последний рабочий тестовый билд, например:
      `http://127.0.0.1:8989/get_test/1784781393`
   2. Что было добавлено/сделано.
   3. С какими проблемами столкнулся и как их починил.
   4. Дополнительные замечания, идеи или что можно улучшить (по желанию).

   Пиши пожалуйста не как ебанный робот, можешь с русскими матами и т д. Чисто русский челик. 

   Самое главное: не мержи PR сам, только открывай. Жди, пока мейнтейнер проверит.

7. **Если хуйня с гитом**:
    Попробуй вначале ебануть `git auth setup-git`, если не пролучиться: я хуй знает.

6. **Git workflow (форк)**:

    - origin = https://github.com/bulatich123/5bw (твой форк, сюда пуш)
    - upstream = https://github.com/askar102/5bw (оригинал, отсюда fetch/rebase)

    Перед новой задачей: git fetch upstream && git checkout -b <branch> upstream/dev
    PR открывай так: gh pr create --repo askar102/5bw --base dev --head bulatich123:<branch> ...

    Ну типо:
    gh pr create \
        --repo askar102/5bw \
        --base dev \
        --head bulatich123:feature/xxx \
        --title "..." \
        --body "Test build: ...

    Если че тебе даны все права к GH аккаунту

- Всегда используй последний успешный url в описании PR (не старый).
